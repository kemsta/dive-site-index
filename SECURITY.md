# Security policy

## Reporting a vulnerability

Do not open a public issue for an exploitable vulnerability, leaked credential, private location, or other sensitive disclosure.

Use GitHub’s private [Report a vulnerability](https://github.com/kemsta/dive-site-index/security/advisories/new) form. Include:

- the affected URL, file, or commit;
- steps to reproduce;
- expected impact;
- suggested mitigation, if known.

If GitHub does not let you access the private form and the report is not sensitive, open a minimal [bug report](https://github.com/kemsta/dive-site-index/issues/new?template=bug-report.yml) asking the maintainer to establish a private contact channel. Do not include exploit details or secrets.

Ordinary factual mistakes, missing sites, attribution questions, and accessibility defects belong in [GitHub Issues](https://github.com/kemsta/dive-site-index/issues).

## Scope

The static site, build pipeline, schemas, and repository automation are in scope. Third-party services, MapLibre, OpenStreetMap infrastructure, and linked source websites are not operated by this project and should normally be reported to their respective maintainers.
